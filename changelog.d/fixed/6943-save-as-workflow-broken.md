The dashboard chat view's "Save as Workflow" button now actually loads the workflow into the canvas.
It previously wrote the extracted JSON to `sessionStorage` under the key `"canvas-draft"`, while the canvas page's `readCanvasDraft()` reads `"canvasDraft"` — the two never agreed, so the hand-off silently no-op'd.
Even with matching keys it still would have failed: the stored payload was the raw `workflow_create` shape (`{name, description, steps, ...}`), not the `{nodes, edges, workflowName, workflowDescription}` shape the canvas page actually parses, so the canvas would have loaded empty with the steps discarded in silence.
`ChatPage.tsx` now imports the canvas page's own `CANVAS_DRAFT_KEY` constant instead of duplicating the literal, and transforms the parsed `steps` into canvas nodes and edges (a new `workflowStepsToCanvasState` helper in `lib/canvas.ts`, mirroring the layout `CanvasPage.loadWorkflowIntoCanvas` already uses for a workflow with no saved layout) before persisting the draft (#6943) (@DaBlitzStein)
