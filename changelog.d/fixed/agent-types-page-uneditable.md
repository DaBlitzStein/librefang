The Agent Types page was unusable on any install where agents outnumber templates: `GET /api/agent-types` merged in every `~/.librefang/workspaces/agents/` directory as `source: "agent"`, and the dashboard has no editor for that source, so every card just showed "Managed via Agents" with no edit or delete button.
The listing now returns only real templates from `~/.librefang/templates/`; every card it lists is editable and deletable with the existing machinery, and the detail routes (`GET /api/agent-types/{name}` and `/toml`) keep resolving a workspace agent by name for backward compatibility.
Spawning a persistent agent "from template" (`POST /api/agents {"template": name}`) also had the opposite bug for as long as it existed: `resolve_manifest` only ever checked `workspaces/agents/`, so it 404'd for every real template and only worked when the name happened to match an existing agent — it now checks `templates/` first, matching the other two template resolvers.
`POST /api/agents/{id}/save-as-agent-type` is new: it extracts a live agent's current manifest into a reusable `templates/<name>.toml` file without touching the source agent's workspace, memory, or sessions, unlike `POST /api/agents/{id}/clone` which duplicates the running instance itself.
This is the bridge from "I have agents, not templates" to a populated, editable Agent Types page (@DaBlitzStein)
