The TUI's model-routing editor (`r` on the agent detail screen) now actually persists the mode, allowed-profile list, and cost budget the operator edits.
Pressing Enter used to just navigate back to the detail screen without ever emitting an `AgentAction` — the code even said so in a comment — so every edit was silently discarded and the operator had no way to know their change never took effect.
There was also no backend route to change `model.mode` / `model.router_override` for an *already-spawned* agent at all: those fields could previously only be set once, at creation time, through the custom-agent wizard's manifest.
Fixed by adding a dedicated `GET`/`PUT /api/agents/{id}/model_routing` route pair, mirroring the existing per-agent `/skills` and `/mcp_servers` endpoints, backed by a new `LibreFangKernel::set_agent_model_routing` that persists to SQLite and `agent.toml` with rollback on failure like its skills/MCP/channel siblings.
The editor now also fetches the agent's real current routing state when opened, instead of reusing whatever `model_mode`/`router_profiles` the previous screen happened to leave behind, so Enter can no longer save a value the operator never actually chose.
While fixing this, found and fixed an adjacent bug in the same code path: the custom-agent creation wizard collected a `router_override` for "flexible" mode but never wrote `mode = "flexible"` to the generated manifest, so a flexible custom agent silently spawned in fixed mode; it also unconditionally wrote `cost_budget = "default"` for the no-cap selection, which is not a valid `CostTier` and would have failed manifest parsing (#7741) (@DaBlitzStein)
