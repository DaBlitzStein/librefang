The honest-reply guard added for #8235 never actually replaced anything: its replacement branch returned `Cow::Borrowed` instead of `Cow::Owned`, so the call sites in both agent loops discarded the substitution and delivered raw `<function=...>` markup to the channel every time recovery failed to parse a text-based tool call.
  Fixing that alone would have been a regression on its own, because the span-stripping helper it depends on dropped every character of prose that followed the last recognized markup span, so a reply that opened with an unparseable call and then answered normally in prose had that real answer replaced by the apology sentence instead.
  Six more defects around the same guard are fixed alongside it: the `<tool_call>` pattern paired with the wrong closing tag, unconditional numeric/boolean guessing on recovered parameter values (now consulting the tool's declared schema instead of corrupting string-typed IDs that merely look numeric), `.trim()` on a recovered value stripping deliberate indentation or a trailing blank line instead of only the single newline the markup convention introduces, the guard not covering token-limit truncation and running before retry classification instead of after it, the block-stall degrade (#5979) having its forced tools-stripped turn undone by recovery promoting the same call back from text, and the streaming path forwarding raw markup live before the post-stream guard ever got a chance to replace it.
  The streaming path now withholds a delta while it might still resolve to pure markup, so the raw syntax never reaches a client rendering deltas as they arrive (#8236) (@DaBlitzStein)
