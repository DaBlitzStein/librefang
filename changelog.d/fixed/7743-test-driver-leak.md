`ephemeral_mission_folder_created_and_cleaned` and `ephemeral_spawn_is_denied_when_parent_is_over_its_cost_quota` in `librefang-kernel` assumed a bare test kernel could never resolve an LLM driver, so `cargo test` made real, billable calls through the `claude` CLI on any machine that has it on `PATH` — and failed outright once the CLI actually answered instead of erroring.
Both tests now boot through a helper that pins `default_model.provider` to a name no provider registers, resets the kernel's live config after boot (which otherwise auto-detects a real provider as its own boot-resilience fallback and leaks it back in), and injects an explicit stub `LlmDriver`, so driver resolution is deterministic regardless of what credentials or CLIs are present in the environment.
The quota test's uncapped control case now asserts the spawn actually succeeds with the stub driver, proving the quota gate specifically permits it, rather than merely producing some other, indistinguishable error.
