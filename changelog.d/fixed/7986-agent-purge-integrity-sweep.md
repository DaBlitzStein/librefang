`librefang purge` now closes several ways an agent's data or identity could survive being purged.
It refuses to run its destructive path while a daemon is detected for the installation (override with `--force`), and resolves the target database through `[memory] sqlite_path` / `data_dir` instead of a hardcoded `<home>/data/librefang.db`, so a custom installation layout is no longer purged against the wrong (or a stale, freshly-created) database.
Orphan-id recovery now reads live agent ids straight from the `agents` table rather than through the hydrating roster loader, which silently drops a row whose manifest fails to deserialize or whose UUID is unparseable — exactly the damaged-row situation that leads an operator to run purge in the first place — and used to make that live agent's rows a false-positive cascade target.
The orphan candidate scan also now runs even when the purged name currently has a live roster entry, so residue left by an *earlier* incarnation of the same name (recreated under a different id since) is found and removed instead of surviving under the report "nothing to purge".
A manifest-supplied workspace path is no longer deleted blindly: `workspace = "."` resolving to the workspaces root itself, or to a directory another still-registered agent's manifest also resolves to, is now detected and left alone rather than wiping out data that belongs to every agent or to a different one.
A hand agent's absolute `workspace` override (`<workspaces>/hands/<hand>/<role>`) is now resolved against the whole workspaces root instead of failing validation against the `agents/` subtree alone, which used to report "no manifest survives for this agent" for a hand agent that was very much alive.
Cron jobs and event triggers are keyed by `AgentId`, and the default id is derived deterministically from the agent's name, so purge now removes them for the purged id(s) too — without this, a new agent later spawned under the purged name would silently inherit the old agent's cron schedule and event wiring outright.
Channel and conversation routing bindings, which key on the agent's *name* rather than its id, are now cleared the same way, closing the equivalent inheritance path for `/agent` routing.
A failed write to `agent_identities.toml` (e.g. a read-only home directory) is now surfaced as a purge failure instead of being reported as a successful removal, since the registry's own `purge()` call only logs a warning on that failure and still returns success.
Finally, an id that has rows in agent-scoped tables but cannot be attributed to any name — a child or ephemeral agent's `AgentId::new()`, never registered and already gone from the roster — is now reported as present rather than silently ignored, though it is deliberately left untouched: purge has no way to prove it belongs to the requested name, and the safer error is to under-delete.
