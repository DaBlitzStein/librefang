Agents behind a litellm gateway fronting an OpenAI-shaped model group that doesn't forward `reasoning_effort` no longer go silent for 5 minutes on every turn.
litellm was returning `400 UnsupportedParamsError: openai does not support parameters: ['reasoning_effort']` because `ThinkingConfig` defaults to a non-zero budget on every request, and the driver treated any non-retryable error as a provider-health signal for the circuit breaker.
The OpenAI-compatible driver now detects an unsupported-parameter rejection (litellm's `UnsupportedParamsError`, OpenAI's `unsupported_parameter` code, and proxy `unexpected keyword argument` shapes), strips `reasoning_effort` and retries transparently, then remembers the model so it never sends the field to that provider+model combination again.
The provider circuit breaker (`ProviderCooldown`) now excludes this specific, deterministic 400 class from its failure count — a genuine bad-request, auth, or model-not-found 400 still opens the circuit as before (@DaBlitzStein)
