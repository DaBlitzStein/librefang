History trimming can no longer drop the current turn's task message.
`safe_trim_messages` only guaranteed that *some* user message survived the trim, so a tiny `max_history` could drain the message that initiated the current turn while an earlier user turn remained — leaving the model to answer a question it could no longer see. The trim now captures the current-turn task (the last user message of the turn-shaped history) before trimming and re-appends it, in both the working copy and the persisted session, whenever the trim would otherwise have dropped it.
