`GET /api/models?provider=<gateway>` returned zero models for a self-hosted OpenAI-compatible gateway (litellm, a vLLM/llama.cpp proxy registered under its own provider id, …) even when the gateway was reachable and actively serving completions.
`list_models` only ever refreshed a live catalog for OpenRouter and EveryAPI; every other provider was served from the static registry snapshot, which by definition never contains an operator-defined gateway's model ids.
A new `custom_gateway_catalog` module mirrors the existing OpenRouter/EveryAPI refreshers — same TTL, same per-base-URL retry window, same warn-and-degrade-to-static-snapshot behaviour on a down or slow gateway — and applies automatically to any provider unknown to the built-in driver registry (i.e. an operator-defined id, not a curated provider like `openai` or `groq`), with a configured base URL and a usable auth state.
No opt-in toggle is required, matching how OpenRouter/EveryAPI already behave.
When the gateway also exposes litellm's optional `/v1/model/info` extension, declared context-window / output-limit / per-token cost figures are used; when it doesn't (or reports them as `null`, as the reporting litellm instance did), the model still appears in the list with the catalog's existing "unknown" sentinel rather than being hidden (#7775, #7827) (@DaBlitzStein)
