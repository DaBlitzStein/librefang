Deleting a sidecar channel now clears every adapter the channel owns, not a guessed one.
The orphan-reconcile branch removed the plain adapter key plus a `{name}:{name}` qualified key, but the bridge registers qualified adapters as `{name}:{account_id}` using the adapter's own account id — so `{name}:{name}` only ever matched the coincidence where the two are equal, and on any multi-account deployment the real entry survived every delete and every reload, which is precisely the non-converging orphan that branch was added to resolve.
Separately, the recursive scan that decides which files a delete may rewrite enforced only two of the three rules the kernel applies to a config include: it rejected absolute paths and `..` components, both of which are string checks, but never verified that the resolved path is still inside the including file's directory once symlinks are followed.
A relative symlink in the config directory pointing outside it passed both checks, resolved, parsed, and — if it declared `sidecar_channels` — joined the list the handler rewrites, so the endpoint could edit a file the kernel itself would refuse to merge.
