`DELETE /api/channels/sidecar/{name}` used to look for the channel's `[[sidecar_channels]]` block in the root config.toml only, so a sidecar declared through an `include = [...]` file was deleted from nowhere and the endpoint answered 404 for a channel that was running at that moment.
The delete now walks every config file that declares the name — root and all includes — because a name declared in both at once made the early return leave the survivor behind and the reload re-merge it, reporting `removed` while the channel came back.
A running daemon that outlived its config edit still holds the channel in memory with nothing left to strip; that state is now reconciled with a config reload plus a forced bridge restart (which stops the orphaned child process) instead of 404, and only a name declared nowhere still answers 404.
The include scan itself was first-level and substring-only, so a channel declared two includes deep, or through the inline `sidecar_channels = [...]` form, was invisible to it and still 404ed while live; it now resolves includes recursively and parses each file instead of matching text, staying within the same absolute-path and `..`-traversal limits the kernel enforces, and a missing include is tolerated on delete (it cannot declare a block) while `configure`'s conflict check keeps failing closed on one.
The cross-file strip was atomic per file but not across the set, so a later file failing to write could leave an earlier file's block already gone with no way to retry; every candidate file is now snapshotted before the first write and restored on any failure.
A stale channel adapter left with no config anywhere never cleared on its own, because the map is normally cleared only by a config-reload diff that this exact state produces empty, so every repeat delete tore down and restarted every other sidecar for nothing; the reconcile path now drops the stale adapter key directly.
A duplicate `[[sidecar_channels]]` entry for the same name in one file was only ever stripped once, leaving the survivor to be re-merged on reload; every matching entry in a file is now removed.
