Bound how many uploads may be mid-flight at once, closing a RAM ceiling the body-limit fix above narrowed but reopened.
`upload_file` buffers the whole request body into RAM via `axum::body::Bytes` before the handler runs, and nothing in the crate bounded concurrency on that path — only per-request caps existed.
Before the body-limit fix the implicit ceiling from axum's own 2 MiB extractor default kept N concurrent uploads under roughly `N * 2 MiB`; raising `max_upload_size_bytes` to cover real attachments raised that same multiplier, so an operator who set it to 100 MB to accept PDFs could see ~4 GB of resident memory from 40 parallel uploads.
A new `max_concurrent_uploads` setting (default 8) now gates the upload routes with a semaphore acquired before the body is extracted, so peak RAM from this path is bounded to `max_concurrent_uploads * max_upload_size_bytes` regardless of how many requests arrive; a caller past the cap gets an immediate 429 rather than queuing (#8185) (@DaBlitzStein)
