`/new`, `/reboot`, `/compact` and file attachments on a channel turn now resolve their target session id through one function, `LibreFangKernel::channel_session_id`, instead of four independently hand-rolled `for_sender_scope` calls that could silently drift apart.
For the three reset commands the derivation is byte-identical to before on every caller that exists today, because the channel-side sender context already sanitizes reserved channel names before a reset command ever sees them — this closes no live command-side bug, it makes the drift class structurally impossible.
The attachment resolver was the fourth mirror and the only one without the reserved-name guard, but it was not reachable either: every production caller either passes no sender context, requests the canonical session, or builds the sender context through `request_sender_context`, which sanitizes the channel name at construction time, so migrating it closes the drift class, not a live bug.
The `/new` ack now counts the session's own pre-wipe row, read under the same lock the delete takes rather than a second read, and excludes the system messages a prior reset's configured `reset_prompt` injected, so a true no-op second `/new` reports 0 instead of the previous reset's injected message count.
It also carries the agent's name, so a broadcast `/new` reply is self-identifying. (#7701) (@DaBlitzStein)
