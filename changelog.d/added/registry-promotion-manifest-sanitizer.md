Add `sanitize_agent_manifest_for_publication` and `detect_private_manifest_fields` to `librefang-types::agent`, the groundwork for an upcoming "promote to registry" button that publishes a deployed agent's manifest as a public agent type via PR.
A live instance's `agent.toml` carries operator-private data the registry validator does not check for — absolute workspace paths, `api_key_env` / `base_url` credentials on the model and every fallback, external workspace mounts, host-specific `exec_policy`, literal `context_injection` text, and `is_hand` / instance metadata — none of which belongs in a public repository.
The sanitizer strips all of that while preserving the portable agent-type fields (name, description, system prompt, provider/model, skills, tools, channels, routing, tags); the detector independently scans the manifest for absolute paths, credential-shaped strings, and internal hostnames — including in fields the sanitizer leaves untouched, like `system_prompt` — so a promotion UI can show the operator what will be exposed before they publish, not just clean up silently.
