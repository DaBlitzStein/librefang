New `librefang purge --agent <name>` CLI command removes every trace of an agent the operator already deleted: any roster entry left over (cascading to its sessions, memories and KV rows), orphaned sessions/memories/KV rows left behind by a previous partial delete even when the roster entry is already gone, the agent's canonical UUID record in `agent_identities.toml`, the workspace directory, and any agent-type template of the same name.
The command reads the canonical `agent-types` store via `agent_type_path_in`, prompts for confirmation before deleting (with `--yes` to skip — required when stdin is not a TTY) and offers `--dry-run` to print the exact `PurgeReport` it would produce without changing anything (#7986) (@DaBlitzStein)
